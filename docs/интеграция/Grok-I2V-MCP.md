# Grok I2V через owner MCP

Статус группы — **экспериментальная**. Этот локальный контракт не подтверждает
все варианты модели, стабильность провайдера или фактическое списание.
19 октября 2026 через MCP получено реальное видео для `grok_15_i2v` с запросом
`1:1`, `5` секунд и `480p`: один MP4, H.264, 544×544, длительность 5,042 секунды,
с аудиодорожкой AAC. Был один POST генерации; результат получен GET-проверкой.
Это подтверждение только этого варианта, не всех настроек и не legacy `grok_i2v`.

Поддерживаются два явных `model_id`:

| Модель | Локальная начальная поддержка |
| --- | --- |
| `grok_i2v` | Только уже подготовленное изображение 16:9, длительность 6 или 10 секунд, локальная граница prompt 5 000 UTF-16 units |
| `grok_15_i2v` | Соотношения 16:9, 9:16, 3:2, 2:3, 4:3, 3:4 и 1:1; длительность целым числом от 1 до 15 секунд; локальная граница prompt 2 000 UTF-16 units |

Обе модели принимают явное разрешение `480p` или `720p`. Поле `seed` в этом
контракте не поддерживается. Все параметры обязательны: начальные значения
формы `16:9`, `5` секунд и `480p` не подставляются автоматически и не
считаются доказанными эффективными defaults.

## Включение owner stdio

Группа выключена по умолчанию. Можно напечатать конфигурацию так:

```sh
node scripts/print-media-mcp-config.mjs --confirm-enable-paid-tools --include-grok-i2v
```

Helper выдаёт placeholder destination. Перед использованием замените его на
одно из двух явных значений:

```json
{
  "SYNTX_OWNER_GROK_I2V": "1",
  "SYNTX_OWNER_GROK_I2V_UPLOAD_DESTINATION": "<uploaded|hidden>"
}
```

Destination задаётся оператором, а не параметром MCP-вызова. Значение по
умолчанию UI-формы для этих моделей не подтверждено. Helper печатает общий
owner-media конфиг; оставьте только необходимые группы и заполните или удалите
placeholders остальных.

## Загрузка и генерация

Инструменты:

1. `syntx_owner_upload_grok_i2v_image` принимает `link_attempt_id`, `model_id`,
   `filename`, `mime_type` и padded `content_base64`. Поле соотношения сторон в
   upload вызове отсутствует. Один файл должен быть JPEG/JPG, PNG или WebP.
2. `syntx_owner_generate_grok_i2v_video` принимает `link_attempt_id`, точный
   `model_id`, `prompt`, `aspect_ratio`, `video_duration`, `resolution` и
   непрозрачный `reference_handle`. Поле `seed` запрещено.
3. `syntx_owner_get_grok_i2v_result` выполняет только GET-проверку по
   `recovery_id`.
4. `syntx_owner_list_grok_i2v_recoveries` показывает recovery текущего
   `link_attempt_id` в работающем процессе.

Пример для начального среза `grok_i2v`:

```json
{
  "link_attempt_id": "<current linked attempt>",
  "model_id": "grok_i2v",
  "prompt": "A slow cinematic camera move.",
  "aspect_ratio": "16:9",
  "video_duration": 6,
  "resolution": "480p",
  "reference_handle": "<handle from upload>"
}
```

Для `grok_i2v` изображение должно уже иметь соотношение 16:9. Локальная
проверка не выполняет crop или resize. Для `grok_15_i2v` разрешены семь
указанных соотношений; этот интерфейс параметров сам не меняет размер файла.
Каталог ограничивает количество изображений одним, но upload receipt и
provider acceptance остаются отдельными проверками.

Локальный предел обработки составляет 20 MiB для `grok_i2v` и 10 MiB для
`grok_15_i2v`. Это ограничения ресурсов локального процесса, а не пределы
провайдера. Каталог отмечает `grok_15_i2v` как preferred/default вариант;
оператор всё равно передаёт точный model ID, автоматического выбора модели нет.

До создания чата и перед отправкой generation service заново проверяет
доступность модели, подписку, свежую цену и баланс. Сравнение цены с балансом
— наблюдение доступности, а не жёсткий лимит списания. Если ответ POST
неопределён, не повторяйте генерацию: используйте только GET-инструмент
результата. Handles живут 15 минут; операции и recovery хранятся в памяти
процесса и теряются после его перезапуска.
