# WAN 2.7 I2V через MCP

Начальный срез точной модели `wan_27_i2v`, не соседние R2V, Edit или T2V. Один
результат этого среза восстановлен через MCP с привязкой к текущему индексу,
истории и detail-запросу; остальные настройки и модели этим не подтверждаются.

## Включение

```sh
node scripts/print-media-mcp-config.mjs --confirm-enable-paid-tools --include-wan27-i2v
```

Замените `SYNTX_OWNER_WAN27_I2V_UPLOAD_DESTINATION` на доверенный выбор
`uploaded` или `hidden`. Флаг `SYNTX_OWNER_WAN27_I2V` выключен по умолчанию.
Печать шаблона не меняет настройки клиента, не входит в аккаунт и не генерирует.
Общий шаблон содержит другие owner-группы: оставьте только необходимые.

## Начальные параметры

Один первый кадр, явный prompt до 1500 UTF-16 units, `resolution:"720P"`,
`aspect_ratio:"1:1"`, `video_duration:5`, `prompt_extend:false`,
`shot_type:"single"`, `audio_setting:"auto"`, `seed:null`,
`native_audio:false`, `rendering_speed:"basic"`. Другие значения этим
начальным срезом не включены. В wire изображение имеет роль `first_frame`.
Последний кадр, видео, аудио и автоматическая обрезка не поддерживаются.

Локальная проверка принимает JPEG/JPG, PNG, BMP и WebP до 20 MiB, стороны
240–8000 и aspect ratio 0.125–8; это проверка контейнера, не декодирование
всех пикселей и не гарантия приёма провайдером.

## Работа

После обычного Telegram-входа вызовите `syntx_owner_upload_wan27_i2v_image`
с `link_attempt_id`, точным `model_id`, именем, MIME и `content_base64`.
Полученный `image_handle` передайте в `syntx_owner_generate_wan27_i2v_video`
с тем же link attempt и явными начальными параметрами. Handle не раскрывает
URL и привязан к аккаунту, native-клиенту и 15-минутному сроку жизни.

Перед созданием собственного чата и POST сервис читает подписку, баланс и
quote с `resolution` и `video_duration`. Это проверка средств, не жёсткий
лимит стоимости. Каждый POST платный и вызывается явно.

`syntx_owner_reconcile_wan27_i2v_video` принимает исходный `recovery_id` и
читает только собственный чат/сообщение; `syntx_owner_list_wan27_i2v_recoveries`
показывает записи текущего процесса. При неизвестном исходе не повторяйте
upload или GEN. Recovery не переживает перезапуск. Наличие ссылки означает
наблюдаемую доступность артефакта, а не доказанный terminal status или billing.

## Наблюдённый начальный результат

Read-only reader2367 сделал один index GET, шесть history GET и шесть detail
GET; upload и generation вызовов не было. Для начального запроса
`720P`/`1:1`/5 с возвращено связанное видео H.264 размером 960×960. Видеопоток
измерен в 5.000 с; контейнер с AAC длится 5.038 с и имеет размер 1 049 573
байт. Доказательство связано с текущим индексом, history и detail
(`CURRENT_LINK_INDEX_HISTORY_DETAIL_BOUND`, gaps 0).

Полученный квадратный файл не доказывает, что запрошенный `720P` гарантирует
конкретное выходное разрешение. Длительность видеопотока и контейнера различна;
не следует описывать результат как ровно пятисекундный файл. Это один
наблюдённый tuple, не подтверждение всех настроек, provider terminal status или
billing.
