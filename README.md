# SYNTX MCP — изображения, видео и аудио

MCP-сервер для работы с SYNTX из Codex, Claude Code и других MCP-клиентов.
Локальный запуск использует stdio; для облачного ChatGPT предусмотрен отдельный
HTTPS-шлюз с OAuth. Каждый пользователь входит в собственный аккаунт SYNTX
через Telegram. Лицензия — [MIT](LICENSE).

## Что доступно

- Поиск моделей, их параметры, условия доступности, баланс и подписка.
- Загрузка исходников, генерация и чтение результатов для реализованных
  семейств изображений, видео и аудио; получение ссылок на медиа.
- Отдельные инструменты редактирования, референсов, кадров, озвучки и музыки.
- Встроенная карта маршрутов, инструкции обслуживания и обновление кода.

Текущая карта — [v6](catalog/media-coverage/owner-tool-routes-v6.json):
127 media ID, из них 120 активных. Для 119 активных генераторов существуют
code bindings; ещё один активный ID — селектор семейства. По типам это
48 моделей изображений, 71 видео и 8 аудио, включая неактивные записи.
Две новые неактивные GPT Image 2.6 записи доступны для обнаружения и не
включают новую генерацию. Исторические каталоги и карты v1–v5 сохранены.

Запрашивайте `syntx_get_media_coverage` постранично, чтобы получить всю карту.
`tools/list` работающего сервера показывает фактически включённые инструменты
и их входные схемы. Code binding, параметры из исходников интерфейса,
синтетический тест и реальная генерация — разные виды подтверждения.
Исторический native-профиль E551 сохранён; новые ветви имеют отдельные
source-профили. Доступ по вашему тарифу проверяется отдельно.

## Локальная установка: Windows, macOS, Linux

Установите Git, Node.js 24.21.x или совместимую проверенную версию 24.x,
FFmpeg и FFprobe. Затем:

```sh
git clone https://github.com/alexfisenkov/syntx-mcp.git
cd syntx-mcp
npm ci
npm run build
node scripts/print-media-mcp-config.mjs --confirm-enable-paid-tools --include-all-supported-media --include-self-update
```

Последняя команда выводит JSON для настройки вашего MCP-клиента. Она не меняет
конфигурацию клиента, не входит в аккаунт и не запускает генерацию.
Сохраните выведенное подключение в клиенте. Укажите доверенные абсолютные пути
к `ffmpeg` и `ffprobe` в `SYNTX_MEDIA_FFMPEG_PATH` и
`SYNTX_MEDIA_FFPROBE_PATH`. Замените каждое значение `<uploaded|hidden>` на
`uploaded` либо `hidden`. JSON-пути Windows должны содержать экранированные
обратные слеши. Не переносите пути другого компьютера без изменения.

`--include-all-supported-media` включает реализованные группы текущего
выпуска. Неизвестные будущие модели автоматически исполняться не начинают.
`--include-self-update` отдельно включает локальные инструменты обновления.
Платная генерация вызывается явно и расходует баланс SYNTX. Сборка TypeScript
может использовать до 4 GiB heap; это предел сборки, а не память MCP runtime.

Для локальной загрузки изображений по пути добавьте к printer-команде
`--local-image-root "/абсолютный/каталог/моих/исходников"`. Будут доступны только
разрешённые корни. Если клиент передаёт байты или файл-вложение, доступ к
произвольной файловой системе для этого не нужен.

## Вход и первый результат

1. Попросите агента выполнить обычный вход в SYNTX: `syntx_begin_login`,
   подтверждение через Telegram и `syntx_check_login`. Каждый пользователь
   подтверждает свой вход. Не передавайте агенту пароль Telegram или сессию.
2. Запросите `syntx_get_account_status`: баланс, активность и срок подписки.
   Отсутствующее поле остаётся неизвестным; MCP не покупает и не продлевает тариф.
3. Выберите модель и получите её параметры соответствующим read-only
   инструментом `syntx_get_…`. Укажите настройки по фактической схеме.
4. Загрузите нужные исходники инструментом этой модели. Передайте возвращённые
   непрозрачные handles в генерацию. Handles привязаны к владельцу, текущему
   входу и модели; время их действия ограничено. Произвольный URL не заменяет
   принадлежащий вам исходник.
5. Получите результат или выполните предусмотренный GET-only recovery той же
   операции. Если исход неизвестен, не повторяйте платный запрос вслепую.

Например: «Покажи доступные параметры Banana 2.1, используй приложенное фото
как референс и создай изображение 3:4»; «Покажи режимы Seedance и создай короткое
видео по этим исходникам»; «Найди подходящий голос ElevenLabs и озвучь текст».
Агент должен сначала сверить модель, настройки, доступность и цену.

Telegram MCP — отдельный необязательный companion:
[telegram-mcp-starter](https://github.com/alexfisenkov/telegram-mcp-starter).
Он может помогать с обычным подтверждением входа только через собственный
Telegram пользователя и при его разрешении. SYNTX MCP не требует копирования
Telegram-сессии или credentials в свой репозиторий.

## ChatGPT в облаке и собственный VPS

Разверните отдельный owner HTTPS MCP с OAuth, затем добавьте его в ChatGPT.
Пошаговая инструкция, Linux helper, конфигурация своего reverse proxy,
терминальное одобрение OAuth и обновление:
[HTTPS MCP для ChatGPT и VPS](deploy/README.md).

Шлюз принимает Streamable HTTP, поддерживает DCR и PKCE S256. OAuth-подключение
разрешает доступ к вашему MCP; обычный Telegram-вход затем связывает SYNTX.
Не подключайте других пользователей к одному приватному owner-профилю.

В HTTPS-режиме разрешённые инструменты бинарного ввода объявляют
`_meta["openai/fileParams"]`. Вложение ChatGPT превращается в проверенные байты
для исходного инструмента, после чего действуют проверки конкретной модели.
Загрузки ограничены по размеру, времени и источнику; по умолчанию разрешён
`files.oaiusercontent.com`. Это политика этого сервера, а не обещание домена
любой будущей ссылки ChatGPT. Результаты возвращаются как MCP content,
structuredContent и ссылки на артефакты; отображение зависит от клиента.

Старый loopback HTTP transport остаётся отдельной read-only поверхностью;
его не нужно публиковать в интернет вместо OAuth-шлюза. Альтернативный
[Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)
требует отдельного официального tunnel-client; printer в этом проекте только
помогает составить конфигурацию, не устанавливает туннель.

## Как обновить MCP

Включив локальный self-update, скажите агенту: «Проверь обновление SYNTX MCP
и установи доступную версию». Либо в чистом source checkout:

```sh
node scripts/update-mcp.mjs check
node scripts/update-mcp.mjs apply
```

Обновление подготовит точный опубликованный commit в отдельном каталоге,
установит locked-зависимости, соберёт его и выберет для следующего запуска.
Текущий MCP-процесс сам не перезапускается. Сначала получите результаты
незавершённых операций, затем перезапустите MCP в клиенте и обновите список
инструментов. Для отката:

```sh
node scripts/update-mcp.mjs rollback
```

Не удаляйте старые выпуски и lock, пока updater или MCP может работать.
Изменённый checkout, fork, свежий ZIP/npx не являются исходной установкой
для этого self-update. Используйте чистый checkout официального репозитория.
VPS обновляется оператором через доверенный терминал по инструкции HTTPS;
удалённый MCP-клиент не получает произвольный shell или self-update сервера.

Обновление опубликованного кода и адаптация новой формы SYNTX — разные задачи.
Встроенный skill `syntx-mcp-update` помогает сравнить каталоги, исходники
настроек и затронутые участки. Он не генерирует непроверенную интеграцию
автоматически. Подробнее: [обновление MCP](docs/интеграция/Обновление-MCP.md).

## Проверки и эксплуатация

- CI запускается для конкретного commit. `media-cloud-final` объединяет
  целевые Linux-проверки и отдельную Windows-приёмку с настоящими FFmpeg/FFprobe,
  путями с пробелами/кириллицей/emoji, SDK и проверкой завершения процессов.
- `npm run test:media:update` проверяет затронутый медиа-срез; финальный
  clean-package smoke отдельно проверяет собранный распространяемый пакет.
- CI использует синтетические аккаунты и не расходует SYNTX-токены.
  Проверка реального провайдера и приёмка облачного ChatGPT выполняются отдельно.
- При потере ответа после мутации HTTPS-шлюз оставляет дочерний runtime живым
  и закрывает новые мутации до разбора исхода. Legacy handles и эта блокировка
  находятся в процессе; после рестарта они не восстанавливаются. Автоматический
  рестарт сам не повторяет генерацию. Перед перезапуском разберите неизвестные
  операции; отсутствие handle после сбоя не доказывает отсутствия платной работы.
- Проверка цены и баланса не является гарантированным провайдером hard cap.
  Срок жизни ссылок, изменения тарифа и отказ модели определяет SYNTX.
